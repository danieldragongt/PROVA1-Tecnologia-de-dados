GUIA DE ESTUDO DETALHADO E DIDÁTICO

1. Conceitos Básicos: Dado, Informação e SGBD (Aula 01)

Para entender bancos de dados, o primeiro passo é saber a diferença entre o elemento bruto e o elemento interpretado[cite: 1]:

  • Dado: É um valor solto, um símbolo ou número sem contexto[cite: 1]. Não possui significado direto e não permite tomar decisões por si só.
    Exemplo: 220, B3, 100.
  • Informação: É o dado processado, organizado e contextualizado[cite: 1]. A informação gera conhecimento e permite ação ou tomada de decisão.
    Exemplo: "A máquina B3 opera em uma tensão de 220V e exige 100 amperes."
SGBD (Sistema Gerenciador de Banco de Dados): É o programa encarregado de guardar, consultar, alterar e proteger os dados, isolando o usuário da complexidade física de armazenamento no disco (ex.: PostgreSQL, MySQL, SQL Server, Oracle).

2. Diagrama Entidade-Relacionamento (DER) (Aulas 02 a 04)

O DER é o modelo conceitual: um mapa visual que desenha o negócio de forma abstrata antes de programar as tabelas[cite: 1].

2.1. Componentes Principais

  • Entidade (Retângulo): Representa objetos ou conceitos do mundo real sobre os quais desejamos guardar informações[cite: 1] (ex.: EQUIPAMENTO, MANUTENCAO).
  • Atributo (Elipse/Óvalo): As características da entidade[cite: 1].
    • Simples: Indivisível (ex.: CPF).
    • Composto: Pode ser dividido (ex.: Endereco que se divide em Rua, Numero e Bairro).
    • Multivalorado: Pode ter vários valores para a mesma entidade (ex.: Telefone de um cliente, representado com elipse dupla).
  • Relacionamento (Losango): A ação ou associação entre entidades[cite: 1] (ex.: TECNICO executa MANUTENCAO).

2.2. Cardinalidade

Mede a quantidade mínima e máxima de conexões entre os elementos[cite: 1]:

  • 1:1 (Um para Um): Cada elemento de A se liga no máximo a um elemento de B[cite: 1].
  • 1:N (Um para Muitos): Um elemento de A se liga a vários de B, mas um elemento de B se liga a apenas um de A[cite: 1].
  • N:M (Muitos para Muitos): Múltiplos elementos de A se ligam a múltiplos elementos de B[cite: 1].

2.3. Casos Especiais do DER

  • Relacionamento Ternário: Envolve três entidades ao mesmo tempo para formar um sentido lógico completo[cite: 1] (ex.: TECNICO aplica PECA em um EQUIPAMENTO).
  • Entidade Associativa: Criada obrigatoriamente para quebrar um relacionamento N:M[cite: 1]. Surge quando a própria ligação precisa guardar atributos (ex.: no relacionamento N:M entre ALUNO e DISCIPLINA, cria-se a entidade associativa MATRICULA para guardar a Nota).
  • Entidade Fraca: Entidade que não consegue se identificar sozinha e depende obrigatoriamente de uma entidade "forte" (ex.: DEPENDENTE só existe se associado a um FUNCIONARIO)[cite: 1].
  • Generalização e Especialização (Herança):
    • Generalização: Cria uma entidade pai abstrata (ex.: VEICULO).
    • Especialização: Cria entidades filhas herdando atributos do pai e adicionando características próprias (ex.: CARRO e MOTO)[cite: 1].

3. Modelo Relacional e Mapeamento (Aula 05)

É o modelo lógico: o momento em que o desenho (DER) é transformado em **tabelas reais** com linhas e colunas[cite: 1].

3.1. Tipos de Chaves

  • Chave Candidata: Qualquer coluna (ou conjunto de colunas) capaz de identificar de forma única uma linha da tabela[cite: 1].
  • Chave Primária (Primary Key - PK): É a chave candidata escolhida para ser o identificador oficial da tabela[cite: 1]. Regra de Ouro: Nunca aceita valores nulos (NULL) nem duplicados.
  • Chave Estrangeira (Foreign Key - FK): É a Chave Primária de outra tabela inserida nesta tabela para criar o vínculo/ponte entre elas[cite: 1].
  • Chave Composta: Chave primária formada por duas ou mais colunas juntas[cite: 1].
Integridade Referencial: Regra que garante a consistência do banco[cite: 1]. Exige que o valor de uma Chave Estrangeira (FK) deve obrigatoriamente existir como Chave Primária (PK) na tabela pai, evitando cadastros "órfãos"[cite: 1].

4. Normalização de Dados (Aula 06)

Processo de organização das tabelas para **eliminar a duplicação de dados (redundância)** e evitar erros durante inserções, alterações ou remoções[cite: 1].

  • 1ª Forma Normal (1FN) — Atomicidade: Todos os valores das células devem ser indivisíveis[cite: 1]. Proibido ter listas ou múltiplos valores no mesmo quadrado (ex.: dois telefones juntos)[cite: 1].
  • 2ª Forma Normal (2FN) — Dependência Total da Chave: Deve estar na 1FN e **todos os atributos não-chave devem depender inteiramente de TODA a chave primária** (aplica-se a tabelas com chave composta)[cite: 1].
  • 3ª Forma Normal (3FN) — Sem Dependências Transitivas: Deve estar na 2FN e **nenhum atributo não-chave pode depender de outro atributo não-chave**[cite: 1]. Todos devem depender diretamente apenas da Chave Primária[cite: 1].

5. Questões de Concurso para Treino

Questão 1 (Dado vs. Informação - FGV)

Analise as afirmações abaixo sobre conceitos de banco de dados:

I. O número "120" armazenado isoladamente em um banco de dados representa uma informação.
II. A consolidação do número "120" associado ao contexto "unidades do produto X em estoque na fábrica A" representa uma informação.
III. O SGBD é o conjunto de dados armazenados sem o software de gerenciamento.

Está correto apenas o que se afirma em:

  • a) I.
  • b) II.
  • c) III.
  • d) I e II.
  • e) II e III.
Questão 2 (Mapeamento DER - CESPE / CEBRASPE)

Acerca da modelagem conceitual de dados utilizando o Diagrama Entidade-Relacionamento (DER), assinale a opção correta[cite: 1]:

  • a) Uma entidade fraca possui identificação própria e independente de outras entidades no modelo[cite: 1].
  • b) O relacionamento do tipo Muitos para Muitos (N:M) deve ser mapeado diretamente no modelo relacional mantendo-se apenas as duas tabelas originais sem tabelas auxiliares.
  • c) A entidade associativa é utilizada para mapear um relacionamento N:M quando há necessidade de registrar atributos pertencentes ao próprio relacionamento[cite: 1].
  • d) Os atributos multivalorados podem ser armazenados diretamente em uma única coluna atômica na 1FN.
Questão 3 (Chaves e Integridade - FCC)

Em um banco de dados relacional, a garantia de que o valor de uma chave estrangeira em uma tabela filha deve obrigatoriamente corresponder a um valor existente da chave primária na tabela pai é denominada[cite: 1]:

  • a) Integridade de Entidade.
  • b) Integridade Referencial.
  • c) Normalização de Dados.
  • d) Dependência Transitiva.
  • e) Especialização de Atributo.
Questão 4 (Normalização - VUNESP)

Uma tabela que possui atributos não chave dependendo apenas de uma parte de uma chave primária composta viola as regras de qual Forma Normal[cite: 1]?

  • a) Primeira Forma Normal (1FN).
  • b) Segunda Forma Normal (2FN).
  • c) Terceira Forma Normal (3FN).
  • d) Forma Normal de Boyce-Codd (FNBC).
  • e) Quarta Forma Normal (4FN).

6. Gabarito Comentado

Questão 1: Resposta B.
Comentário: A afirmativa I está incorreta pois "120" solto é apenas um **dado**[cite: 1]. A afirmativa II está correta pois o contexto transforma o dado em **informação**[cite: 1]. A III está incorreta pois o SGBD é o software gerenciador.

Questão 2: Resposta C.
Comentário: A entidade associativa é usada exatamente para quebrar relações N:M e armazenar dados da própria ligação (como data ou nota)[cite: 1]. A opção A está errada pois a entidade fraca depende de outra[cite: 1].

Questão 3: Resposta B.
Comentário: O conceito de associar uma Chave Estrangeira (FK) a uma Chave Primária (PK) existente define a **Integridade Referencial**[cite: 1].

Questão 4: Resposta B.
Comentário: A **2FN** proíbe dependências parciais em chaves primárias compostas[cite: 1]. Todos os campos devem depender da chave inteira[cite: 1].
